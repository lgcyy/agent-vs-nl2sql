# DiFT 第二轮：效果有多强，消融究竟证明了什么

**后续进度（2026-10-30）：**用户决定暂不优先考虑 DiFT 方法，后续学习转向[MFTCoder](02-mftcoder.md)。本文保留证据与分析，不把个人方法取舍写成已证明方法无效。

日期：**2026-10-30**。[上一轮：方法与参数行选择](01-dift.md) · [论文卡片](../papers/a-01-dift.md) · [逐项数字与重算记录](../resources/dift-mix-evidence.json)

**当前判断：**DiFT 有值得学习的参数选择思路，但对“一个混训 checkpoint 同时恢复两个目标”的解决证据有限。把它放在第一篇是为了对齐问题，不代表它是业务效果最好的方案。以下分开记录论文报告、根据原表重算的结果，以及本仓库自己的数学例子和判断。没有运行训练或复现实验。

## 1. 先回答“效果是不是真的不太好”

以本仓库希望解决的双侧回退为尺度，效果说服力确实偏弱；不过，不应只挑一个较差组合概括全篇。[正式论文](https://proceedings.iclr.cc/paper_files/paper/2026/file/b304a04c6a4ac168aa692923814ace17-Paper-Conference.pdf) Table 2 的混训部分为三个组合乘两个模型，共六组。逐一比较两个目标列，得到以下**本仓库的表内重算**：

| 模型 | 目标任务顺序 | DiFT 相对普通混训的两项变化 | 数值分类 |
| --- | --- | --- | --- |
| Llama3-8B | Math / Code | +2.20 / −0.0221 | 一升一降 |
| Llama3-8B | Code / Logic | +0.0580 / +0.83 | 双升 |
| Llama3-8B | Logic / CSQA | −0.06 / +1.55 | 一升一降 |
| Mistral-7B | Math / Code | +1.29 / +0.0516 | 双升 |
| Mistral-7B | Code / Logic | +0.0213 / +1.34 | 双升 |
| Mistral-7B | Logic / CSQA | +0.57 / −0.24 | 一升一降 |

代码保留原 xGLUE 列的计分尺度；其余准确率变化按原表百分数相减，单位为百分点。结果是 **3/6 双升、3/6 一升一降**，没有持平或双降。作者汇总的 ATA 则是 6/6 提高。

再把 Table 1 中两个任务各自单训的目标成绩组成参考向量，比较 DiFT 的两列：**1/6 双升、3/6 一升一降、2/6 双降**。这个参考向量由两个单训模型组成，不声称存在一个单训模型同时取得两项参考成绩。详细数值已逐行保存在 JSON 中。

因此，“平均分改善”“两项比原混训都好”“两项达到各自单训”是三个不同强度的命题；本文主表对它们的支持范围差别很大。

### 贴近当前现象的组合，具体恢复了多少

Mistral-7B Code＋Logic 的代码列，普通混训为 1.2342，DiFT 为 1.2555，对应单训为 1.7146。按原表计算：

$$
\text{填补的单训差距比例}
=\frac{1.2555-1.2342}{1.7146-1.2342}
\approx 4.4\%.
$$

这是本仓库用这一列构造的差距比例，不是作者指标，也不是“代码通过率提升 4.4%”。该比例对这一列的正仿射单位换算不变，但不提供统计显著性或业务价值保证。代码侧虽回到 base 数值以上，距离单训仍较远。

上述全部计数只是六组报告值的描述，不是成功概率或多 seed 统计。尤其 −0.06、−0.24 这样的差值不能据此称为稳定退化。B.5 说明评估三个 checkpoint 后取最好，跨指标是否统一选点未充分交代；所以仍不能把一行数据直接升级为“已核实同一 checkpoint 同时取得两项分数”。代码指标的具体子任务、单位也未充分定义。

## 2. 为什么还值得看消融

先把两个可能解释分开。第一种是“只要少更新参数就能减少扰动”；第二种是“DSR 挑中的位置比随意选择同等规模的位置更适合更新”。普通全参混训与 DiFT 的比较同时改变更新规模和位置，单凭它不能把收益归给第二种解释。

同规模随机选择的对照更接近要回答的问题。D.4 / Table 11（PDF 第 21 页）报告：

| Llama3-8B Math＋Code 混训 | GSM8k | xGLUE |
| --- | ---: | ---: |
| 普通混训 | 64.82 | 1.0956 |
| DSR 选位置的 DiFT | 67.02 | 1.0735 |
| 论文称同规模的随机 DiFT | 62.35 | 1.0294 |

这里有两个必须同时保留的判断。按报告值，DSR 选择比随机选择的两项都好，支持“选择位置包含有用信息”。但相对普通混训，DiFT 仍是数学提高、代码下降，未构成双目标改善。

**证据强度：**作者称随机版本有相同行数／规模，但没有充分给出逐层随机掩码、实际参数计数与随机掩码重复结果，因此目前只能按其所述对照意图理解，不能声称已独立核实严格参数量匹配。该表未给多训练 seed 的均值／误差范围。§3.3 的 seed 42–46 用于 DSR 探测样本抽取，不能当作这里的五次独立训练。

Table 11 的括号差值也不能照抄：混训代码的 1.0294−1.0735 为 −0.0441；原括号 −0.0662 对应的是相对普通混训。连续训练数学的 42.46−46.32 为 −3.86，与括号 −4.03 不符。本笔记采用原始分数独立相减，不把括号的不一致解释为实验造假。

反向 DiFT 把所选集合与其补集交换（§5.5 / Table 4），通常同时改变更新位置和规模，因此它单独提供的定位证据比同规模随机对照更难解释。

## 3. 变化大、位置有用、共同更新兼容，是三个问题

下面是**本仓库自造的一维教学模型**，不来自论文实验。设一层只有一个权重 w，输入恒为 1，所以输出就是 w；起点 w=0。考虑两个可能的任务世界：

| 假设情形 | A 单训目标 | B 单训目标 | A 的输出平方差 | B 的输出平方差 |
| --- | ---: | ---: | ---: | ---: |
| 两任务方向一致 | +1 | +1 | 1 | 1 |
| 两任务方向相反 | +1 | −1 | 1 | 1 |

DSR 式的平方差在两个世界中给出同样的分数。它可以提示这一位置在两种适配中都发生了变化，却不能仅凭分数区分变化方向是否一致。

再为反向情形定义两个假设损失：

$$
L_A(w)=\tfrac12(w-1)^2,\qquad L_B(w)=\tfrac12(w+1)^2.
$$

等权混合得到

$$
L_{\rm mix}(w)=\tfrac12L_A(w)+\tfrac12L_B(w)
=\tfrac12w^2+\tfrac12.
$$

混合最优点是 w=0；两者单训最优点分别为 +1、−1。即使正确选中了这个位置，并且允许更新，仍不能让同一个 w 同时达到两个单训最优点。这个人为构造的模型只说明“定位位置”不自动提供“协调方向”的保证；它不证明真实 SQL 与 Agent 必然不兼容，也没有产生双侧低于起点。

对 DiFT 而言，混训采用各任务所选行的并集，交集也保留（§4.2 / Algorithm 1）。因此，限制更新范围可能减少外围扰动，但集合操作本身没有直接检查共享行上的方向冲突。两个任务所选行不相交，也不等于真正隔离：在同一个并集掩码下，A 数据仍可能更新由 B 选入的行，反之亦然。

## 4. 参数移植增加了什么证据

D.2 / Table 9（PDF 第 20 页）把数学单训与常识单训的所选行互相移植，报告能力分数随移植发生偏移。这个证据比单纯画激活分布更进一步：确实对权重做了干预。

但“改变这组权重会影响表现”仍不等于“这组权重独立且专门存储该能力”。原文没有充分给出同等规模、层分布及修改幅度的随机移植对照；移植也改变了这些行与网络其余部分的搭配。它支持所选位置与行为有关，尚不足以证明唯一能力模块、完整必要性或充分性。

D.2 / Table 10 的缩放同时改变所选并集和补集。对这一干预的结果，也不能把变化全部唯一归因于并集。这里是在限定已有消融的解释范围，没有提出或实施新的实验方案。

## 5. 对“两个业务指标同时低于起点”还缺哪一段解释

以下是**本仓库的独立数学检查**。令两个固定训练目标为 L_A、L_B，正权重混合为

$$
L=\lambda L_A+(1-\lambda)L_B,\qquad 0<\lambda<1.
$$

设 M 是固定的零一对角更新掩码，做理想化梯度下降 θ⁺=θ−ηM∇L。在光滑目标、小步长的一阶近似下：

$$
\Delta L\approx-\eta\,\nabla L^\top M\nabla L\le 0.
$$

所以，同一步更新中，两个固定训练目标不可能在一阶上都严格变差，否则它们的正权重和也会变差。梯度冲突可能造成折中、抵消或偏向某个任务；仅说“梯度冲突”还没有完整解释两个最终业务指标同时低于共同起点。

这不否定用户观察：实际比较的是训练后的业务表现，未必就是这个理想模型中的训练目标；有限步长、随机优化、目标代理与泛化之间也存在差别。本推导不假定用户使用 SGD，不把局部一阶结论扩展为任意优化器或整个训练过程的保证。

对当前 Qwen-3.8-27B 问题，仍需保留的核心区分是：所选位置是否相关、混合更新是否协调、训练目标改善是否转化为 SQL／Agent 业务表现。DiFT 为第一个问题给出了局部经验支持，对后两项没有建立当前业务所需的充分证据。

因此，本仓库维持它的**高阅读相关性**，将其方法价值限定为**参数选择的启发与候选对照**；尚无依据把它定为业务优先实施方案。下一篇 MFTCoder 将继续考察训练目标如何由 token、样本和任务层面的损失汇聚构成。
