## 原文证据

问题是多种推理能力混合或连续 SFT 后难以保持单训表现。DiFT 根据初始模型与任务微调模型的激活差异识别参数行，再按任务组合区别更新。§3 / Table 1 呈现协同与干扰并存；§4 说明方法；§5 / Table 2 主要用目标任务平均分 ATA 汇总改进。[论文全文](https://proceedings.iclr.cc/paper_files/paper/2026/file/b304a04c6a4ac168aa692923814ace17-Paper-Conference.pdf)

附录 B.6 给出**连续数学→逻辑训练**的格式污染个案。它提示评分下降可能包含输出协议变化，但不是对所有退化的证明，也不是本案例混训原因的证据。同一全文的 §5.3 与 Table 2 标注说明了该个案的适用设置。

**本仓库按表内数值所作比较：**混训两列均低于对应单训与共同 base；Table 2 的 DiFT 结果回到两列 base 之上，但代码侧仍低于 Code-only。这比单纯“混训低于单训”的描述更贴近当前观察，不能再仅因作者实现／引用未核全而把它降为一般背景。

**证据限制：**Table 1 的部分上升箭头与相对 base 的数值矛盾；混训代码侧对 base、逻辑侧对单训的差距很小，该行没有给出误差范围。这里是原表数值的谨慎重读，不是稳健普遍双降、因果机制或业务复现的证明。Logic-only 本身也低于逻辑侧 base，不能描述成“两个单训都优于 base”。

**评价口径复核：**B.5 将 xGLUE 列关联到 CodeXGLUE，但具体子任务与计分尺度未充分交代，不能把大于 1 的数值自行转成概率或百分比。该节还称每次训练评估三个 checkpoint 并取最好，跨指标是否使用同一选定 checkpoint 未充分说明；所以这是一组表内相邻比较，尚不足以核实用户设定的全部严格条件。ATA 对该组合使用 `(50 × 代码列 + 逻辑列) / 2`，它的改善不保证每一项均改善。

## 混训方法复核

§4.1 用起点模型和每任务单训模型的激活差为参数行评分；§4.2／式(7)与 Algorithm 1 采用任务相关行的**并集**，在共同起点上混训，仅更新该集合。交集包含在并集内，不能讲成“冲突任务去掉交集”或按任务分别隔离更新。单训模型在此用于定位，混训方案不等同权重合并。

高激活差是任务相关性的代理，不直接测量两任务梯度的冲突方向。模型各自前向时的深层输入也可能不同，输出差不只反映本层权重变化。附录 D.1 的范数／重要性解释依赖额外近似条件，精读讲义给出独立的线性代数检查。

连续 SFT 的 Eq. 8／Algorithm 1 与附录的差集、补集描述存在不一致。本轮准确讲解混训并集规则，不替作者猜定连续版本的完整实施方式。

## 局限与本案例关系（调研判断）

这是最接近“混训低于对应单训”的近期工作之一；它有助于把共享参数干扰与数据组织区分开。其数学、代码、逻辑、常识结果不覆盖 NL2SQL-noCoT 加长程交互轨迹；平均分结论也不等于两个目标域都高于共同起点。不能把本文识别的参数关联直接当作当前业务模型的因果机制。

## 代码核查

**2026-10-30 补充发现：**[官方 Supplemental ZIP](https://proceedings.iclr.cc/paper_files/paper/2026/file/b304a04c6a4ac168aa692923814ace17-Supplemental-Conference.zip)确实包含分析、参数行选择与训练相关源码。公开 GitHub 仓库及 Stars 仍未核实；不能将这两个结论混为一谈。

- `delta_scale_rows_analysis.py`：同一 query＋response 分别前向起点与单训模型，比较相应层输出，累积 token 平方差并按样本数运行平均。对固定数据，除总 token 数与除样本数只差公共常数，不改变逐层 Top-C 排名；逐样本先按长度平均才改变长短样本相对权重。
- `delta_scale_rows_select.py`：逐层读取高分行，汇总多组采样的并／交；并含全局选择分支，示例入口为逐层选择。
