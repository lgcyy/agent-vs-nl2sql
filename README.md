# agent-vs-nl2sql

> 此消彼长：专精任务能力与通用 Agent 能力相关研究的调研资料库。

本仓库用于集中保存专题综述、论文阅读笔记与相关资源，以 NL2SQL 和长程 Agent 相关研究为主要切入点，方便持续查阅、补充和引用。

“此消彼长”是调研问题的概括；具体结论以收录材料的适用条件与证据为准。

## 内容入口

| 入口 | 保存什么 |
| --- | --- |
| [专题综述](topics/README.md) | 围绕一个问题，综合多篇论文与其他资料 |
| [论文笔记](papers/README.md) | 单篇论文的研究问题、方法、结论与阅读理解 |
| [相关资源](resources/README.md) | GitHub 项目、官方技术博客、数据集与其他参考资料 |

[专题模板](templates/topic.md) · [论文模板](templates/paper.md)

## 候选整理方向

- **专精能力与通用能力：**能力保持、迁移、遗忘，以及任务之间的关系。
- **数据混合与训练方法：**数据选择、数据配比、长短样本、训练顺序与相关方法。
- **Agent 轨迹质量：**轨迹可靠性、质量检测、筛选、清洗与过程监督。

这些是待整理的方向，可随资料积累调整，尚不代表已有完整综述。Agent 描述交互与执行方式，NL2SQL 描述任务域；整理时需说明各篇工作实际研究的对象。

## 怎么使用

1. 有用的资料先放入相关索引，保留原始链接。
2. 阅读论文后，在 `papers/` 保存笔记，并更新论文索引。
3. 多份材料涉及同一问题时，在 `topics/` 形成专题整理，链接已有笔记与资源。

默认使用中文 Markdown。模板按需使用；图片、附件与单独的汇报版本在实际需要时补充。

## 整理约定

- 保留可核查的来源，优先链接论文原文、作者仓库和官方文档。
- 区分作者结论与整理者的理解；关键结论尽量标注章节、图表或页码。
- 优先关注近期、相关性强、论文与代码齐全的工作，也保留必要的基础工作。
- 项目的关注度、维护状态和内容相关性结合考虑。星数、发表状态等易变信息注明核查日期。
- 未核查的信息标为“待核查”。同一信息尽量只维护一份，通过相对链接关联。
